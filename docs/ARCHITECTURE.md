# Архитектура проекта

HydroCrack Insight развивается как desktop-приложение на PyQt по техническому
заданию из ЛР5. ЛР1-ЛР4 используются как контекст для процессов, моделей и
терминов.

## Проектная граница

Приложение является информационно-аналитической надстройкой над SCADA/DCS. В
учебном прототипе оно может имитировать реакции оборудования, но в реальной
трактовке не заменяет DCS/PLC и не является промышленным управляющим контуром.

## Слои

- `app.ui` - desktop-интерфейс PyQt.
- `app.monitoring` - мониторинг параметров и анализ отклонений.
- `app.equipment` - оборудование и демонстрационное аварийное реагирование.
- `app.resources` - будущий учет расхода ресурсов.
- `app.forecasting` - будущие прогнозы и сценарное моделирование.
- `app.reports` - будущая отчетность и экспорт.
- `app.users` - будущая авторизация и роли.
- `app.journals` - будущие сменные журналы, события и аудит.
- `app.simulation` - учебная имитация источника данных.
- `app.database` - локальное хранение данных.
- `app.domain` - общие термины, роли и реестр подсистем.
- `app.models` - базовые структуры данных, используемые сервисами.
- `app.core` - совместимые обертки для старых импортов.

## Текущий поток данных

1. `SensorSimulator` генерирует состояние процесса.
2. `DeviationAnalyzer` проверяет параметры и возвращает статус.
3. `MainWindow` обновляет интерфейс и сохраняет состояние через `DatabaseService`.
4. При аварии `EmergencyService` меняет демонстрационные статусы оборудования.
5. События, отклонения и статусы оборудования сохраняются в SQLite.

## Целевой поток по ЛР5

1. Источник данных SCADA/DCS или CSV/Excel-импорт передает параметры процесса.
2. Модуль мониторинга валидирует значения и сохраняет их в БД.
3. Модуль технологических ограничений сравнивает параметры с активным режимом.
4. Журналы фиксируют события, действия пользователей и передачу смены.
5. Модули ресурсов, прогнозирования и отчетов рассчитывают KPI и сводки.
6. UI показывает данные пользователям с учетом ролей и прав доступа.

## Роли

Роли закреплены в `app.users.roles`:

- оператор;
- технолог;
- инженер КИПиА/АСУ ТП;
- руководитель;
- администратор.

Реальная авторизация будет добавлена отдельным этапом.
