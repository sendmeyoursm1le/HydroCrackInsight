# Архитектура проекта

HydroCrack Insight развивается как desktop-приложение на PyQt по техническому
заданию из ЛР5. ЛР1-ЛР4 используются как контекст для процессов, моделей и
терминов.

## Проектная граница

Приложение является информационно-аналитической надстройкой над SCADA/DCS. В
учебном прототипе оно может имитировать реакции оборудования, но в реальной
трактовке не заменяет DCS/PLC и не является промышленным управляющим контуром.

## Слои

- `app.ui` - desktop-интерфейс PyQt.
- `app.monitoring` - мониторинг параметров и анализ отклонений.
- `app.equipment` - оборудование и демонстрационное аварийное реагирование.
- `app.resources` - будущий учет расхода ресурсов.
- `app.forecasting` - будущие прогнозы и сценарное моделирование.
- `app.reports` - будущая отчетность и экспорт.
- `app.users` - пользователи, роли, права доступа и текущая сессия.
- `app.journals` - будущие сменные журналы, события и аудит.
- `app.simulation` - учебная имитация источника данных.
- `app.database` - локальное хранение данных.
- `app.domain` - общие термины, роли и реестр подсистем.
- `app.models` - базовые структуры данных, используемые сервисами.
- `app.core` - совместимые обертки для старых импортов.

## Хранилище

SQLite используется как локальная учебная БД. `DatabaseService` создает две
группы таблиц:

- справочники: роли, пользователи, установка, оборудование, датчики и
  технологические режимы;
- операционные данные: агрегированные состояния процесса, показания датчиков,
  отклонения, события, статусы оборудования, планы, ресурсы, рекомендации,
  отчеты, сменный журнал, аудит и лабораторные результаты.

Сервис сохраняет публичные методы MVP, поэтому UI не зависит от деталей SQL.
Это упрощает будущий переход на отдельные репозитории или PostgreSQL.

## Текущий поток данных

1. `SensorSimulator` генерирует состояние процесса.
2. `DatabaseService` загружает активный технологический режим и его уставки.
3. `DeviationAnalyzer` проверяет параметры по активному режиму и возвращает
   статус.
4. `MainWindow` обновляет интерфейс и сохраняет состояние через `DatabaseService`.
5. `DatabaseService` пишет агрегированную историю процесса, строки датчиков и
   строки расхода ресурсов.
6. Таблица параметров строится через `app.monitoring.parameter_snapshot` с
   учетом уставок активного режима.
7. Live-графики трендов обновляются из текущего состояния и последних строк
   `sensor_data`.
8. CSV/Excel-импорт через `ProcessDataImporter` сохраняет внешние учебные данные
   в тот же поток `process_values` и `sensor_data`.
9. При аварии `EmergencyService` меняет демонстрационные статусы оборудования.
10. События, отклонения, рекомендации и статусы оборудования сохраняются в SQLite.
11. При следующем запуске приложение восстанавливает последнее сохраненное
   состояние процесса.
12. Вход пользователя и значимые действия записываются в аудит.
13. При смене пользователя новое окно загружает из БД общие события, отклонения,
   аудит и актуальные статусы оборудования.

## Целевой поток по ЛР5

1. Источник данных SCADA/DCS или CSV/Excel-импорт передает параметры процесса.
2. Модуль мониторинга валидирует значения и сохраняет их в БД.
3. Модуль технологических ограничений сравнивает параметры с активным режимом.
4. Журналы фиксируют события, действия пользователей и передачу смены.
5. Модули ресурсов, прогнозирования и отчетов рассчитывают KPI и сводки.
6. UI показывает данные пользователям с учетом ролей и прав доступа.

## Роли

Роли закреплены в `app.users.roles`:

- оператор;
- технолог;
- инженер КИПиА/АСУ ТП;
- руководитель;
- администратор.

Доступ к вкладкам и действиям описан в `app.users.permissions`. При запуске
`LoginDialog` проверяет пользователя через `DatabaseService`, затем `MainWindow`
строит интерфейс с учетом текущей роли.

Смена пользователя координируется в `ApplicationController`: текущее окно
скрывается, показывается `LoginDialog`, успешная смена записывает `logout` и
`login` в аудит, после чего создается новое окно для выбранной роли.
